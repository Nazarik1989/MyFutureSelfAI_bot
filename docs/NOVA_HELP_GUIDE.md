# Nova Guided Help

Nova помогает найти и открыть уже существующую функцию Future Self AI. Это ограниченный
помощник по интерфейсу бота, а не общий AI-чат и не агент с произвольным доступом к данным.

## Как открыть

- нажать «❓ Помощь» в главном меню;
- отправить `/help`;
- вне активного пошагового сценария явно обратиться: «Nova, …», «помоги в боте …»
  или другой поддерживаемой формой обращения.

`/help` создаёт одно служебное сообщение Nova. Следующий вопрос редактирует это же
каноническое сообщение; пользовательский вопрос не удаляется. Кнопочные переходы также
редактируют текущий экран. Если уже идёт onboarding, check-in, Labs, Vision, загрузка
референса, редактирование задачи или другой flow, Nova не забирает ответ себе и предлагает
явно продолжить текущий шаг либо безопасно выйти в главное меню.

## Локальная помощь и AI fallback

Сначала всегда работает детерминированный локальный resolver. Его каталог строится из
`navigation_actions()`, `navigation_sections()`, `help_topics()`, актуального access tier и
runtime feature flags. Поэтому названия, доступность и кнопки не расходятся с основным
меню. Известный вопрос не вызывает ни одного AI-метода.

AI fallback выключен по умолчанию:

```dotenv
ENABLE_NOVA_AI=false
NOVA_AI_ADMIN_ONLY=true
```

Если оба условия pilot разрешают вызов, fallback доступен только пользователю с tier
`admin`. Guest никогда не вызывает provider; subscriber при admin-only режиме тоже
остаётся на локальном resolver. Blocked не получает Nova session.

Provider получает только:

- текущий вопрос длиной до 600 символов;
- минимальный список разрешённых capability ID, названий и описаний;
- названия включённых runtime features.

Профиль, Telegram ID и имя, задачи, желания, Health/Doctor/Labs, история сообщений,
содержимое БД, референсы и изображения не передаются. Raw-вопрос, prompt и structured
response не сохраняются в БД, session или `context.user_data` и не попадают в логи.

## Безопасные действия

Nova может показать справку, открыть существующий раздел или предложить кнопку запуска
существующего flow. Она не меняет пользовательские данные сама. CTA создаётся только для
server-side allowlist action, привязывается к владельцу, private chat, access version,
canonical message и текущему tier, а случайный token используется однократно. Перед
provider, после него, перед показом CTA и перед его выполнением доступ и feature catalog
проверяются заново.

Неизвестный, выключенный, destructive, access-management или admin-mutation action ID
отбрасывается. Model output не является callback data и никогда напрямую не выбирает
handler. Ещё не реализованные функции — например общая AI-карта будущего — честно
помечаются как недоступные и не получают кнопку запуска.

## Session и ошибки

Nova session хранится только в памяти процесса, живёт 15 минут и не требует миграции.
Она очищается при переходе в главное меню, запуске существующего flow, `/cancel`, истечении
TTL или изменении доступа. После рестарта незавершённая session безопасно отсутствует.

Параллельные вопросы одной session не создают два provider-вызова. Provider timeout или
ошибка дают локальный нейтральный экран без автоматического повтора. Обычная Telegram edit
ошибка не создаёт fallback-сообщение; replacement допускается только для доказанной
несовместимости media/text или отсутствующего canonical message и не более одного раза.
Логи содержат только тип операции и класс ошибки — без вопроса, ответа или Telegram/provider
error body.
